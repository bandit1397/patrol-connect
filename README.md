# 순찰 커넥트 (Patrol Connect)

지정된 순찰 지점들을 OpenStreetMap 위에서 관리하고, 순찰 시작 시 카카오맵으로 실제 길안내를 진행하며, 한 지점에 도착하면 자동으로 다음 가장 가까운 미방문 지점으로 안내를 이어가는 안드로이드 앱입니다.

## 핵심 동작

1. 지도 위에서 주소 검색(OSM Nominatim, 키 불필요) 또는 지도 탭으로 순찰 지점을 등록/삭제합니다.
2. "순찰 시작"을 누르면 현재 위치에서 **직선거리 기준 가장 가까운 미방문 지점**을 계산해 카카오맵 앱으로 길안내를 시작합니다.
3. 해당 지점 반경(기본 50m) 진입을 Geofencing으로 감지하면 지점을 완료 처리(지도 아이콘 색상 변경)하고, 그 지점에서 다시 가장 가까운 미방문 지점을 계산해 자동으로 다음 안내로 넘어갑니다.
4. 자동 전환은 하이브리드 방식입니다: 기기가 허용하면 전체 화면 알림으로 카카오맵을 바로 띄우고, 허용하지 않는 기기에서는 알림을 한 번 탭하면 같은 방식으로 넘어갑니다.
5. 모든 데이터는 각 기기 로컬 DB에만 저장됩니다(서버 없음). 직원별로 완전히 독립적으로 동작합니다.
6. 유료/키가 필요한 API는 전혀 사용하지 않습니다 — OSM 타일, Nominatim(무료 공개 서비스), 카카오맵 URL 딥링크만 사용합니다.

## 이 환경에서 빌드가 안 되는 이유

이 코드를 작성한 환경에는 Android SDK가 설치되어 있지 않아 여기서는 컴파일/실행/테스트를 할 수 없습니다. **Android Studio에서 이 폴더를 열어 빌드해야 합니다.**

### Android Studio에서 시작하는 방법

1. Android Studio → `Open` → `patrol-connect` 폴더 선택
2. Gradle Sync가 자동으로 진행됩니다 (최초 1회 Gradle 8.7 다운로드)
3. 실제 안드로이드 기기(또는 에뮬레이터)를 연결하고 Run

### 꼭 실기기로 테스트해야 하는 부분

- 백그라운드 위치 권한("항상 허용") 부여 흐름
- Geofence 도착 감지 정확도 (에뮬레이터는 GPS 시뮬레이션이 필요)
- 전체 화면 알림 자동 전환 (Android 14+ 기기는 설정에서 수동으로 권한을 켜야 할 수 있음 — 앱이 최초 실행 시 안내 다이얼로그를 띄웁니다)
- 카카오맵 딥링크 실행 (기기에 카카오맵 앱 설치 필요, 없으면 설치 페이지로 이동)

## 배포 (GitHub)

`v*` 형식의 태그를 push하면 `.github/workflows/build-release.yml`이 디버그 서명 APK를 빌드해서 GitHub Release에 자동으로 첨부합니다. 사내 배포이므로 Play 스토어 서명 없이 디버그 서명 APK로 충분합니다.

```
git tag v1.0.0
git push origin v1.0.0
```

직원들은 Release 페이지에서 APK를 다운로드해 "출처를 알 수 없는 앱 설치"를 허용하고 설치하면 됩니다.

## 아직 다듬을 여지가 있는 부분

- 다음 지점 선택은 현재 직선거리 기준입니다. 실제 도로 사정(강, 큰길 등)은 반영하지 않습니다 — 실사용해보고 필요하면 개선하기로 한 부분입니다.
- 순찰 로그는 당일자만 조회 가능하도록 저장됩니다(장기 이력 화면은 아직 없음).

## 웹 테스트 버전 (docs/)

안드로이드 앱을 실기기에 설치하지 않고도 빠르게 테스트해볼 수 있는 브라우저 버전입니다.
`https://<사용자명>.github.io/patrol-connect/` (GitHub Pages, 저장소 Settings → Pages → main 브랜치 `/docs` 폴더로 설정)

**지점은 관리자(배포자)만 지정합니다.** 일반 사용자는 지점을 추가/수정/삭제할 수 없고, 관리자가 배포한
목록 중 순찰할 종류(카테고리)를 선택해서 순찰만 합니다.

- `admin.html` — 관리자 전용 편집 도구. 지도에서 주소 검색/탭으로 지점을 추가하고 종류(예: 금융기관,
  무인점포, 금은방)를 지정한 뒤 "내보내기"로 JSON을 뽑아냅니다. 이 페이지의 편집 내용은 로컬 임시
  작업본일 뿐, **`docs/points.json` 파일 내용을 바꿔서 커밋 & 푸시해야** 실제로 배포됩니다.
- `index.html` — 일반 사용자(경찰관) 화면. `points.json`을 읽기 전용으로 불러와 종류별 탭을 보여주고,
  하나 이상 선택하면 그 종류에 해당하는 지점들만 현재 위치에서 최근접순으로 순찰합니다. 여러 탭을
  동시에 선택하면 두 종류를 합쳐서 순찰합니다.
- `points.json` — 공용 지점 데이터. 관리자만 편집하며, 이 파일을 바꾸는 게 곧 "배포"입니다.

경로를 바꿀 때마다 git 커밋 → push → GitHub Pages 재배포(수십 초~2분)를 거쳐야 사용자 화면에
반영됩니다. 서버 없이 정적 파일만으로 배포하는 구조의 자연스러운 지연입니다.
